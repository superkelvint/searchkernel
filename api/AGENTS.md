# Portable API guidance

This directory owns the normative, language-neutral Portable API. FlatBuffers
is the sole canonical portable data contract.

## Contract and generation rules

- Evolve the canonical `.fbs` schemas here. Do not add a parallel schema,
  full-schema DTO model, or handwritten field-by-field FlatBuffer codec in a
  language SDK.
- Non-Rust RPC uses generated gRPC carrying canonical FlatBuffer bytes.
- Standard schema-aware FlatBuffers JSON is the only JSON representation.
  JSON is converted to FlatBuffer bytes before dispatch; it must not become a
  separate JSON-to-IR semantic path.
- Language SDKs use models generated by `flatc` and the standard generated
  transport stubs, with only a thin idiomatic facade around them.
- Generated Rust protocol code belongs under
  `core/crates/searchkernel-protocol/` and must not be edited by hand.
- Regenerate committed BFBS artifacts and language bindings from the pinned
  FlatBuffers toolchain. Do not hand-edit generated output.

## Compatibility semantics

- FlatBuffers tables are borrowed views over bytes; the portable dispatch path
  converts them into owned Rust values before backend execution.
- Preserve optional-field presence. Missing and explicitly supplied default
  values are not automatically equivalent.
- Union discriminators must agree with their payload tables. Reject malformed
  or incomplete unions at the boundary.
- The schemas describe the portable contract; they do not implement search.

The JSON tooling uses the official FlatBuffers C++ parser and text generator
from FlatBuffers 25.12.19. Use matching headers, libraries, and `flatc` when
regenerating committed BFBS artifacts. Cargo owns the authoritative vendored
headers, library, and compiler; standalone generation scripts may use
`FLATC_PATH` when they verify the same pinned version.
