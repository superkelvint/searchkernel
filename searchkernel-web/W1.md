# W1 Search Lab

The former flow decoded four URL parameters into form state and a second executed-request state, called the adapter's text/browse builder, and rendered a reduced response. Its “JSON” view was a dashboard request echo. Typed queries, predicates, sort clauses, offsets, inputs, and the canonical request/response were absent.

The editor now reads its sole configuration from a versioned URL (`s`). Explicit pure encode/decode/update functions preserve order, reject malformed URL shapes, and reset offsets after semantic edits. Legacy text URLs still work. A valid shared URL executes once on entry; browser navigation reconstructs the configuration. The index target stays in the existing workspace route and all execution uses the existing opened generation-bound handle.

The public TypeScript `SearchRequestBuilder` builds without a transport. `prepareSearch` maps controls into that builder and retains the exact semantic object behind an opaque prepared request. The inspector serializes that same object; execution passes it to the public generation-bound client. Semantic validation and defaults stay in IR. Search Results and the complete response inspector derive from the same decoded SearchResult.

Typed JSON is standard schema-aware FlatBuffers QuerySource JSON, not an additional query language. SDK JSON field names/types come from generated BFBS metadata, including union discriminators. Scalar/container inputs use SDK Value construction; explicit canonical Value objects preserve int64/uint64 and tensors. JSON errors and malformed unions are reported before transport. Backend field/type/profile errors remain canonical.

Controls include text/browse, canonical typed query nodes/annotations (with an ergonomic field/term helper), multiple structured comparison/in/exists filters, ordered field sorts with reordering, offset/limit, profiles and summaries, and typed inputs. Query-family and field compatibility remain daemon decisions. No backend query semantics, defaults, sorting, filtering, or pagination are implemented in React.

Request, executed request, full response, and structured error inspectors are independently accessible and copyable. Results render arbitrary fields as safe formatted JSON. A request retains previous successful results while loading, prevents duplicate submission, supports cancellation, and distinguishes initial/zero-hit/canonical/transport failures. Page controls require an explicit limit and issue backend offset/limit requests.

Verification uses `./dev test --remote frontend`, `./dev test --remote frontend-real-engine`, `./dev test --remote typescript`, and canonical CI/protocol consistency checks. W1 extends the real daemon/Chromium integration with predicates, ordered results, page movement, ranking-input scores, canonical inspectors, shared URLs, reload/back/forward, empty/error/loading states. Immutable F-series artifacts are unchanged; their candidate state does not define W1 implementation evidence.
